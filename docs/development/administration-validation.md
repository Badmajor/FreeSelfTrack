## Rehearsal boundaries and findings

* Clean/legacy full-stack test uses fresh `fst038-*` Compose projects, unique volumes and local
  published test ports. It builds current source and removes containers/volumes in `finally`.
* Legacy fixture contains an owner without project membership, a soft-deleted organization,
  tasks/workflow/links/chat, ready MinIO bytes, old history/security events and a session.
  Existing dedicated PostgreSQL tests cover inactive owners, missing org grants and concurrent
  bootstrap. No production data was copied.
* `pg_dump`/`pg_restore` into a second empty database compares journal/chat/link/workflow/file
  metadata; independent bucket restoration compares SHA-256. Upgrade compares preserved rows,
  checks archived owner backfill and reads old ready bytes through the new API.
* The reviewed maintenance SQL revokes old sessions with one technical event per actual revoke;
  repeating it adds nothing. API/bootstrap/SMTP/deadline/scanner/cleanup use a non-owner runtime
  role. Runtime attempts to create tables, disable triggers or mutate journals are rejected.
* The historical TASK-033 test used current ORM/head before downgrade to 0022. Pinning its schema
  round trip to 0023 and using frozen SQL resolves the test defect; applied migrations and product
  behavior are unchanged. Product defects, if discovered, return to their owning task.
* Contract review found the design-time email-request FK still described as RESTRICT.
  TASK-036 migration 0025 and its PostgreSQL test already implement CASCADE for the ephemeral
  request; ADR-014 now records that delivered behavior. No applied migration changed and no
  user deletion API was added.
* The older full attachment smoke still assumed automatic creator membership. Its fixture now
  adds explicit organization/project memberships through HTTP before task creation, matching
  TASK-033/034. This changes test setup only, not product authorization.
* Default Compose remains a local owner-credential setup. Shared deployment uses the added runtime
  command override and explicit migration/cutover procedure; this is an operator responsibility.
* Backups of real volumes, deployment-specific IAM/TLS/SMTP, capacity and maintenance duration must
  be rehearsed by the operator. Synthetic acceptance cannot certify a particular production host.
* Existing architectural/product/task folders are Git-ignored. Review those files explicitly and
  add intended documents with `git add -f` when preparing a commit; ordinary diff omits them.


A Docker daemon interruption caused one teardown error after three successful attachment tests.
Once Docker recovered, only that disposable project's resources were removed, and the full suite
was rerun successfully. No shared containers, databases or volumes were restarted or migrated.
