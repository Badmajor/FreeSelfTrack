# TASK-008: Frontend tests

## Goal

Создать поддерживаемый набор автоматизированных тестов frontend, который подтверждает основные пользовательские сценарии приложения и предотвращает регрессии Kanban, аутентификации и уведомлений.

---

## Context

Сейчас frontend настроен для запуска Vitest, Testing Library и `jsdom`, но тестовых сценариев нет. TASK-008 закрепляет ожидаемое поведение интерфейса тестами и является тестовым основанием для TASK-005 и TASK-007.

Тесты должны проверять пользовательское поведение через публичный интерфейс компонентов, а не детали реализации React-компонентов или внутреннее состояние запросов.

---

## Requirements

### Functional requirements

* Проверить отображение workspace с организациями и проектами и открытие Kanban отдельным действием.
* Проверить загрузку Kanban с колонками, задачами и независимым состоянием загрузки колонок.
* Проверить создание задачи внутри выбранной колонки.
* Проверить смену статуса задачи через drag-and-drop или доступное меню статуса.
* Проверить дозагрузку задач колонки по cursor при прокрутке.
* Проверить открытие и закрытие панели задачи.
* Проверить редактирование названия и описания задачи.
* Проверить отображение исполнителя, постановщика и наблюдателей согласно доступам, определённым API.
* Проверить уведомления, unread-счётчик и автоматическую отметку уведомления прочитанным при открытии.
* Проверить отображение ошибок API и возможность повторить неуспешную операцию, если такой сценарий предусмотрен интерфейсом.
* Проверить permission-состояния participant controls: доступ владельца, reporter, assignee и обычного участника.
* Проверить откат или синхронизацию UI после отказа mutation для reporter, assignee и watcher.

### Technical requirements

* Использовать существующий Vitest, Testing Library, `user-event` и `jsdom`.
* Запрашивать backend через mock API boundary; тесты не должны требовать запущенного backend или PostgreSQL.
* Зафиксировать единый способ создания QueryClient и тестовых провайдеров.
* Изолировать `localStorage`, timers и mock API между тестами.
* Не использовать snapshot-тесты как единственную проверку поведения.
* Тесты должны быть детерминированными и запускаться в CI без браузера.
* Команда `npm test` должна завершаться ошибкой при падении любого теста и не должна использовать режим `--passWithNoTests` после добавления набора тестов.

## Domain

Задача не изменяет доменные сущности и не вводит новые правила. Тесты должны закреплять существующие frontend-контракты:

* Kanban-колонки производны от статусов проекта.
* Статус задачи принадлежит тому же проекту, что и задача.
* Участники и уведомления приходят с backend и не вычисляются frontend самостоятельно.
* Ширина колонки является локальной пользовательской настройкой и не изменяет workflow проекта.

---

## Architecture

Затрагивается только frontend и его тестовая инфраструктура:

* тестовые providers и fixtures;
* компоненты workspace, Kanban, панели задачи и уведомлений;
* frontend API boundary и mock handlers;
* конфигурация Vitest.

Backend, API и база данных не изменяются.

---

## API

Тесты используют mock API boundary и проверяют вызовы frontend-клиента для существующих контрактов, включая:

```text
GET /api/projects/{project_id}/board
GET /api/projects/{project_id}/tasks/{task_id}
POST /api/projects/{project_id}/tasks
PATCH /api/tasks/{task_id}
GET /api/tasks/{task_id}/watchers
POST /api/tasks/{task_id}/watchers
DELETE /api/tasks/{task_id}/watchers/{watcher_id}
GET /api/notifications
GET /api/notifications/unread-count
POST /api/notifications/{notification_id}/open
```

Тесты не должны изменять API-контракт и не должны обращаться к реальному серверу.

## Authorization

Frontend-тесты должны проверять реакцию интерфейса на ответы backend:

* пользователь видит только доступные организации, проекты и задачи;
* запрещённое действие не показывается или отображает понятную ошибку;
* frontend не считает операцию успешной до успешного ответа API.

Проверка самой авторизации и границ доступа остаётся ответственностью backend-тестов.

---

## Frontend

Тесты покрывают desktop-сценарии TASK-005 и связанные состояния TASK-007:

* workspace и переход в Kanban;
* колонки, карточки, cursor-дозагрузка и локальная ширина колонок;
* создание и редактирование задачи;
* панель задачи и управление участниками;
* список уведомлений и unread-счётчик;
* loading, empty и error states;
* keyboard-доступность кнопок, полей и закрытия панели.

Мобильная адаптация в рамках этой задачи не тестируется, так как TASK-005 ограничен desktop.
