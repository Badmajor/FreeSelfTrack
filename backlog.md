# Backlog MVP трекера

## EPIC 1. Авторизация и пользователи

### AUTH-1 — Регистрация

**User Story:**
Как пользователь, я хочу зарегистрироваться, чтобы получить доступ к системе.

**Acceptance Criteria:**

* регистрация по email/паролю;
* email уникален;
* пароль валидируется;
* после регистрации создаётся пользователь;
* пользователь может войти в систему.

**Backend:** API + модель User
**Frontend:** форма регистрации
**QA:** позитивные/негативные сценарии

---

### AUTH-2 — Авторизация

* login;
* logout;
* access token;
* refresh/session;
* обработка истёкшей сессии.

---

### AUTH-3 — Профиль пользователя
* Уточнено в TASK-010: обязательные имя и фамилия при регистрации, отдельное редактирование профиля и отображение имени в истории задачи.

* имя;
* фамилия;
* email;
* аватар;
* часовой пояс;
* изменение пароля.

---

# EPIC 7. Kanban

Это центральная часть MVP.

## KANBAN-1 — Доска проекта

URL:

```text
/projects/{project_id}/board
```

Колонки автоматически строятся из:

```text
ProjectStatus
```

---

## KANBAN-2 — Карточка задачи

Показывать:

```text
RIDE-123
Исправить авторизацию

👤 Иван
🔴 High
#backend
📅 01.10
```

---

## KANBAN-3 — Drag & Drop

Перемещение:

```text
In Progress → Review
```

должно:

1. изменить `task.status_id`;
2. создать History;
3. отправить уведомление;
4. обновить UI.

---

## KANBAN-4 — Создание задачи из колонки

В колонке:

```text
+ Добавить задачу
```

Новая задача автоматически получает:

```text
status = текущая колонка
```

---

## KANBAN-5 — Настройка колонок

Администратор управляет:

* количеством колонок;
* названием;
* цветом;
* порядком.

---

## KANBAN-6 — Ширина колонок

Пользователь может менять ширину:

```text
Backlog       250px
In Progress   350px
Review        300px
Done          250px
```

Настройки сохраняются для каждого пользователя и проекта

```text
UserProjectBoardSettings
```

Например:

```text
user_id
project_id
column_id
width
position
```

При этом `position` статуса и пользовательское визуальное расположение лучше **не смешивать**: порядок workflow — настройка проекта, ширина — персональная настройка пользователя.

## TASK-012 — Интерфейс добавления колонок в доску

Реализована в Kanban форма создания новых колонок проекта через `ProjectStatus`; добавлены owner-only права, loading/error-состояния и тесты.

## TASK-013 — Изменение порядка колонок Kanban

Добавить владельцу доски drag-and-drop для изменения порядка `ProjectStatus` с сохранением через существующий reorder API и откатом при ошибке.


## TASK-014 — Отдельная страница участников организации и проекта

Добавить отдельную страницу со списками участников и добавлением зарегистрированных пользователей по email через существующий API. Управление доступно владельцу соответствующего ресурса; участник проекта должен состоять в организации. Формы не загромождают workspace и Kanban. Реализовано; статус: DONE. Подробности: [TASK-014](docs/tasks/TASK-014.md).
